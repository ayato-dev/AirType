# Airtype

Лёгкий ИИ-переводчик и редактор для любого поля ввода на Windows, macOS и Linux (X11). Пишешь сообщение где угодно (Telegram, браузер, почта, Slack), жмёшь сочетание клавиш, и текст на месте заменяется переводом или исправленной версией.

Ядро на Rust (Tauri 2), интерфейс на чистом TypeScript без фреймворков. В простое приложение висит в трее и почти не тратит ресурсы.

## Как пользоваться

| Сочетание | Что делает |
|---|---|
| `Ctrl+Alt+T` / `⌘⌥T` | Перевести на твой язык (English по умолчанию). Если текст уже на нём, переводит на второй язык (Русский) |
| `Ctrl+Alt+R` / `⌘⌥R` | Исправить орфографию, грамматику и пунктуацию |
| `Ctrl+Alt+E` / `⌘⌥E` | Улучшить: переписать понятнее и естественнее |
| `Ctrl+Alt+Space` / `⌘⌥A` | Панель под полем: «напиши за меня» или действия с выделенным текстом |

Выдели текст и нажми сочетание. Если выделен кусок, обработается только он, а если ничего не выделено, Airtype возьмёт всё содержимое поля, где стоит курсор. Пока нейронка думает, под полем висит маленький ярлычок на стекле (если места снизу нет, то над полем). Отменить замену можно обычным `Ctrl+Z` / `⌘Z`.

**Панель.** В пустом поле сочетание панели открывает под ним строку: пишешь, что нужно («вежливо откажись от встречи в пятницу»), выбираешь язык и тон, и нейронка пишет текст прямо в поле. Если выделить текст где угодно, даже на сайте, где его не поменять, панель предложит перевести его на выбранный язык, исправить, улучшить, сделать твоё действие или то, что впишешь сам. Ответ сначала показывается в панели: его можно вставить на место выделенного или скопировать.

В настройках можно поменять сочетания, языки, модель и добавить свои действия со своей инструкцией, например «сделай вежливее и короче».

## Ключ API

Airtype работает с твоим собственным ключом (BYOK). Ключ хранится в системной связке ключей (Keychain на macOS, диспетчер учётных данных на Windows, GNOME Keyring или KWallet на Linux), а не в файле.

- **Claude**: ключ берётся в [консоли Anthropic](https://platform.claude.com/settings/keys). По умолчанию стоит `claude-haiku-5-5` с низким усилием: он отвечает быстрее всех и стоит в разы дешевле; если важнее качество текста, выбери `claude-opus-5-5`.
- **OpenAI-совместимый**: OpenAI, OpenRouter (`https://openrouter.ai/api/v1`), локальные Ollama (`http://localhost:11434/v1`) и LM Studio. Для локальной модели ключ не нужен. Ключ уходит только по `https`; по `http` можно ходить лишь на `localhost`.

- **Модель на компьютере**: Qwen3.5 2B (1,3 ГБ) или 4B (2,7 ГБ) через [llama.cpp](https://github.com/ggml-org/llama.cpp). Скачивается прямо из настроек («Модель → модель на компьютере»), работает без ключа и без интернета. Пока модель запущена, она занимает 2–4 ГБ памяти, а через 10 минут без дела выгружается. Есть для Windows, macOS и Linux, на x64 и ARM.

Если API Anthropic недоступен из твоей страны, включи VPN или укажи свой прокси в «Модель → Свой адрес API», либо используй OpenRouter.

## Установка

Установщики лежат в [релизах](https://github.com/ayato-dev/AirType/releases/latest): `.exe` или `.msi` для Windows, `.dmg` для macOS (универсальный, Intel и Apple Silicon), `.deb` и `.AppImage` для Linux на X11.

Новый релиз делается тегом: подними версию в `package.json`, `src-tauri/Cargo.toml` и `src-tauri/tauri.conf.json`, затем `git tag v0.2.0 && git push origin v0.2.0` или на вкладке **Actions** → **build** → **Run workflow** с галочкой «release». GitHub Actions соберёт установщики на трёх системах и сам опубликует релиз. Сборки с каждого пуша в `main` тоже есть: вкладка **Actions** → запуск **build** → артефакты.

**macOS.** Сборка не подписана сертификатом Apple, поэтому после установки выполни один раз:

```sh
xattr -cr /Applications/Airtype.app
```

При первом запуске macOS попросит доступ «Универсальный доступ» (Accessibility): без него приложение не может нажимать `⌘C`/`⌘V` за тебя. Включи Airtype в «Системные настройки → Конфиденциальность и безопасность → Универсальный доступ». Пока сборка подписана ad-hoc, macOS считает каждое обновление новым приложением и сбрасывает этот доступ, его приходится выдать заново.

Чтобы доступ и Keychain переживали обновления, нужна подпись Developer ID и нотаризация. Это делается один раз в своём аккаунте Apple Developer: получить сертификат «Developer ID Application», положить его и данные для нотаризации в секреты репозитория (`APPLE_CERTIFICATE`, `APPLE_CERTIFICATE_PASSWORD`, `APPLE_SIGNING_IDENTITY`, `APPLE_ID`, `APPLE_PASSWORD`, `APPLE_TEAM_ID`), передать их в шаг `tauri build` и убрать `"signingIdentity": "-"` из `tauri.conf.json`. Подробно: https://v2.tauri.app/distribute/sign/macos/

**Windows.** SmartScreen может предупредить о неизвестном издателе: «Подробнее» → «Выполнить в любом случае».

## Разработка

Нужны Rust (stable), Node.js 22 и [системные зависимости Tauri](https://tauri.app/start/prerequisites/).

```sh
npm install
npm run tauri dev     # запуск с горячей перезагрузкой интерфейса
npm run tauri build   # установщик в src-tauri/target/release/bundle
cd src-tauri && cargo test
```

### Как устроено

```
src-tauri/src/
  engine.rs   один прогон: берём текст, зовём модель, ставим ответ на место
  panel.rs    панель под полем: «напиши за меня» и действия с выделенным
  local.rs    модель на компьютере: скачивание llama.cpp и Qwen, запуск сервера
  popup.rs    где показать ярлычок и панель: под полем или над ним
  glass.rs    стекло под окнами (acrylic на Windows)
  field.rs    текст поля через accessibility API (AX на macOS, UI Automation на Windows)
  input.rs    нажатия Ctrl/Cmd+C, A, V по физическим кодам клавиш (работает в любой раскладке; на Linux через XTest)
  clipboard.rs снимок буфера обмена со всеми форматами и возврат как было
  llm.rs      Claude Messages API, OpenAI-совместимый chat/completions и модель на компьютере
  hotkeys.rs  глобальные сочетания, срабатывают на отпускание клавиши
  hud.rs      ярлычок под полем, который никогда не забирает фокус
  config.rs   настройки (JSON в папке приложения) и ключи (системная связка ключей)
  tray.rs     иконка в трее: настройки, пауза, выход
src/          окно настроек, ярлычок и панель (TypeScript + CSS)
design/       исходники иконки и значка в трее
```

Окно настроек на macOS стоит на системном стекле (Liquid Glass в macOS 26, на старых версиях обычная полупрозрачная подложка), на Windows на acrylic. Идея интерфейса взята у корректора: единственный цвет это маркер, выбранное выделено им, а в замечаниях проблемное место подчёркнуто волной, как опечатка. Шрифт Ysabeau Office лежит внутри приложения (`src/assets/fonts`, лицензия OFL), сеть для интерфейса не нужна.

Текст Airtype сначала спрашивает у самого поля через accessibility API: так буфер обмена не трогается, видно, выделено что-то или нет, а поля паролей пропускаются совсем. На macOS ответ тоже пишется прямо в поле (в веб-страницах вставкой, так страница его точно заметит). Короткий ответ в одну строку Airtype просто печатает, как будто набираешь его сам. Длинный на Windows вставляется через `Ctrl+V`, чтобы работала отмена, но в буфер обмена кладётся только обещание: текст отдаётся в момент, когда приложение его попросит, и сразу после этого буфер возвращается как был, так что скопированное раньше не теряется. Если приложение не рассказывает о своих полях, Airtype по-старому жмёт `Ctrl/Cmd+C` и тут же возвращает буфер обратно, ещё до запроса к нейронке. А если текст поменялся, пока нейронка думала, или вставить некуда, ответ не вставляется поверх, а показывается в панели, откуда его можно скопировать.

Текст уходит только в выбранный тобой API. Буфер обмена после вставки возвращается как был, со всеми форматами: картинки, файлы, форматированный текст. Временные данные помечаются так, чтобы не попадать в историю буфера (Win+V и менеджеры буфера на macOS). Если ответ модели обрезан по лимиту, он не вставляется.

Окно настроек создаётся, только когда его открываешь, и закрывается полностью, так что в фоне Airtype не держит лишний веб-движок. Если файл настроек не прочитался, Airtype откладывает его рядом и говорит об этом, а не затирает.

### Ограничения прототипа

- В терминалах Airtype работает только с выделенным текстом: на Windows `Ctrl+C` без выделения прервал бы запущенную программу, а `Ctrl+A` взял бы всю историю. Встроенные терминалы редакторов (VS Code и т. п.) так не распознаются. На Linux в терминалах Airtype копирует и вставляет через `Ctrl+Shift+C`/`Ctrl+Shift+V`, а в xterm и urxvt не работает: там нет сочетания, которое копирует и не прерывает программу.
- На Windows из буфера не восстанавливаются форматы, которые хранят не данные, а дескрипторы GDI (метафайлы, палитры); картинка возвращается как `CF_DIB`.
- Путь через accessibility API ещё не проверен вживую на разных приложениях; Electron-приложения на macOS Airtype на время одного действия просит построить дерево доступности, а потом выключает его обратно.
- Linux работает только в сессии X11: там сочетания ловятся через X, а `Ctrl+C`/`Ctrl+V` нажимаются через XTest. На Wayland система не даёт приложениям ни ловить глобальные сочетания, ни нажимать клавиши за тебя, так что там Airtype сработает лишь в приложениях под XWayland. Текст из полей берётся только через буфер обмена, и после вставки в нём восстанавливается только текст.
