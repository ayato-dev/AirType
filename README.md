# Airtype

Лёгкий ИИ-переводчик и редактор для любого поля ввода на Windows и macOS. Пишешь сообщение где угодно (Telegram, браузер, почта, Slack), жмёшь сочетание клавиш, и текст на месте заменяется переводом или исправленной версией.

Ядро на Rust (Tauri 2), интерфейс на чистом TypeScript без фреймворков. В простое приложение висит в трее и почти не тратит ресурсы.

## Как пользоваться

| Сочетание | Что делает |
|---|---|
| `Ctrl+Alt+T` / `⌘⌥T` | Перевести на твой язык (English по умолчанию). Если текст уже на нём, переводит на второй язык (Русский) |
| `Ctrl+Alt+R` / `⌘⌥R` | Исправить орфографию, грамматику и пунктуацию |
| `Ctrl+Alt+E` / `⌘⌥E` | Улучшить: переписать понятнее и естественнее |

Выдели текст и нажми сочетание. Если ничего не выделено, Airtype возьмёт всё содержимое поля, где стоит курсор. Пока нейронка думает, внизу экрана висит маленький индикатор. Отменить замену можно обычным `Ctrl+Z` / `⌘Z`.

В настройках можно поменять сочетания, языки, модель и добавить свои действия со своей инструкцией, например «сделай вежливее и короче».

## Ключ API

Airtype работает с твоим собственным ключом (BYOK). Ключ хранится в системной связке ключей (Keychain на macOS, диспетчер учётных данных на Windows), а не в файле.

- **Claude**: ключ берётся в [консоли Anthropic](https://platform.claude.com/settings/keys). По умолчанию стоит `claude-opus-5-5` с низким усилием; если хочется быстрее и дешевле, выбери `claude-haiku-5-5`.
- **OpenAI-совместимый**: OpenAI, OpenRouter (`https://openrouter.ai/api/v1`), локальные Ollama (`http://localhost:11434/v1`) и LM Studio. Для локальной модели ключ не нужен.

Если API Anthropic недоступен из твоей страны, включи VPN или укажи свой прокси в «Модель → Свой адрес API», либо используй OpenRouter.

## Установка

Готовые сборки собирает GitHub Actions: вкладка **Actions** → последний запуск **build** → артефакты `airtype-windows` (`.exe`/`.msi`), `airtype-macos` (`.dmg`, универсальный для Intel и Apple Silicon) и `airtype-linux` (`.AppImage` и `.deb`). При пуше тега `v*` создаётся черновик релиза со всеми файлами.

**macOS.** Сборка не подписана сертификатом Apple, поэтому после установки выполни один раз:

```sh
xattr -cr /Applications/Airtype.app
```

При первом запуске macOS попросит доступ «Универсальный доступ» (Accessibility): без него приложение не может нажимать `⌘C`/`⌘V` за тебя. Включи Airtype в «Системные настройки → Конфиденциальность и безопасность → Универсальный доступ». После обновления неподписанной сборки доступ иногда приходится выдать заново.

**Windows.** SmartScreen может предупредить о неизвестном издателе: «Подробнее» → «Выполнить в любом случае».

## Разработка

Нужны Rust (stable), Node.js 22 и [системные зависимости Tauri](https://tauri.app/start/prerequisites/).

```sh
npm install
npm run tauri dev     # запуск с горячей перезагрузкой интерфейса
npm run tauri build   # установщик в src-tauri/target/release/bundle
cd src-tauri && cargo test
```

### Как устроено

```
src-tauri/src/
  engine.rs   один прогон: берём текст, зовём модель, ставим ответ на место
  field.rs    текст поля через accessibility API (AX на macOS, UI Automation на Windows)
  input.rs    нажатия Ctrl/Cmd+C, A, V по физическим кодам клавиш (работает в любой раскладке; на Linux через XTest)
  llm.rs      Claude Messages API и OpenAI-совместимый chat/completions
  hotkeys.rs  глобальные сочетания, срабатывают на отпускание клавиши
  hud.rs      индикатор, который никогда не забирает фокус
  config.rs   настройки (JSON в папке приложения) и ключи (системная связка ключей)
  tray.rs     иконка в трее: настройки, пауза, выход
src/          окно настроек и индикатор (TypeScript + CSS)
design/       исходники иконки и значка в трее
```

Окно настроек на macOS стоит на системном стекле (Liquid Glass в macOS 26, на старых версиях обычная полупрозрачная подложка), на Windows на acrylic. Идея интерфейса взята у корректора: единственный цвет это маркер, выбранное выделено им, а в замечаниях проблемное место подчёркнуто волной, как опечатка. Шрифт Ysabeau Office лежит внутри приложения (`src/assets/fonts`, лицензия OFL), сеть для интерфейса не нужна.

Текст Airtype сначала спрашивает у самого поля через accessibility API: так буфер обмена не трогается, видно, выделено что-то или нет, а поля паролей пропускаются совсем. На macOS ответ тоже пишется прямо в поле (в веб-страницах вставкой, так страница его точно заметит), на Windows вставляется через `Ctrl+V`, чтобы работала отмена. Если приложение не рассказывает о своих полях, Airtype по-старому жмёт `Ctrl/Cmd+C`. А если текст поменялся, пока нейронка думала, ответ не вставляется поверх, а остаётся в буфере обмена.

Текст уходит только в выбранный тобой API. Буфер обмена после вставки возвращается как был; временные данные помечаются так, чтобы не попадать в историю буфера (Win+V и менеджеры буфера на macOS).

### Ограничения прототипа

- Когда текст идёт через буфер обмена, восстанавливается только текстовое содержимое; если там лежала картинка или файлы, они пропадут.
- В терминалах и некоторых редакторах `Ctrl+A` и `Ctrl+C` ведут себя по-своему, там лучше выделять текст вручную.
- Путь через accessibility API ещё не проверен вживую на разных приложениях; Electron-приложения на macOS отдают свои поля только со второго раза.
- Linux работает только в сессии X11: там сочетания ловятся через X, а `Ctrl+C`/`Ctrl+V` нажимаются через XTest. На Wayland система не даёт приложениям ни ловить глобальные сочетания, ни нажимать клавиши за тебя, так что там Airtype сработает лишь в приложениях под XWayland. Ключи на Linux лежат в Secret Service (GNOME Keyring или KWallet), текст из полей берётся только через буфер обмена.
